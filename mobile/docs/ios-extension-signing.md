# iOS widget extension signing proof (TC-788)

`ExoWidgets` is a small iOS 26 WidgetKit extension with the **Record a Voice Note** Control Center / Lock Screen control (kind `xyz.tinycloud.exo.record`) and the recording Live Activity. It has no App Group or entitlements. The recording intents (`App/Shared/RecordingIntents.swift`) are compiled into both the app and the extension; as `AudioRecordingIntent` + `LiveActivityIntent` they perform in the app process, which owns the microphone. An extension-process invocation logs `EXO_SHORTCUT … reached the widget extension` and does nothing. See [capture-ios.md](capture-ios.md#recording-shortcuts) for the shortcut surfaces.

The xcodeproj change is generated by `ruby mobile/ios/scripts/add-widget-extension.rb` (requires the `xcodeproj` gem). The command is idempotent and retains `objectVersion = 60` for Xcode 26.6.

## Build and inspect

```sh
bun install --frozen-lockfile
bun run build:packages && bun run build:frontend
bun run --cwd mobile sync ios
xcodebuild -project mobile/ios/App/App.xcodeproj -scheme App -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/exo-t9-derived CODE_SIGNING_ALLOWED=NO build
EXO_SMOKE_RUNTIME=com.apple.CoreSimulator.SimRuntime.iOS-26-0 \
  mobile/scripts/ios-simulator-smoke.sh run \
  /tmp/exo-t9-derived/Build/Products/Debug-iphonesimulator/App.app /tmp/exo-t9-smoke
xcodebuild -project mobile/ios/App/App.xcodeproj -target ExoWidgets -configuration Release \
  -showBuildSettings | rg 'PRODUCT_BUNDLE_IDENTIFIER|IPHONEOS_DEPLOYMENT_TARGET|CODE_SIGN_ENTITLEMENTS'
xcodebuild -project mobile/ios/App/App.xcodeproj -target ExoWidgets -configuration Release \
  EXO_BUNDLE_ID=xyz.tinycloud.home.dev -showBuildSettings | rg PRODUCT_BUNDLE_IDENTIFIER
```

For a signed device build, activate Node 22 or newer and use T2's `mobile/scripts/ios-device-install.sh` with `UDID=00008140-0006645414D2801C`, `TEAM=R4QVKA785H`, and `BUNDLE=xyz.tinycloud.home.dev`. Check `pgrep -fl 'devicectl device install|adb .*install'` before installing; never uninstall TinyCloud Home. Inspect both `App.app` and `App.app/PlugIns/ExoWidgets.appex` with `codesign -dvv` and `security cms -D -i …/embedded.mobileprovision`, checking team, bundle IDs, and expiry.

## On-device check

1. Add **Record a Voice Note** from the Controls gallery to Control Center and the Lock Screen. Lock the phone and tap it: recording starts and the **Recording** Live Activity appears on the Lock Screen and in the Dynamic Island. Its Stop button saves the note. Filter device logs for `EXO_SHORTCUT`; `source=control` with no `reached the widget extension` line proves app-process routing.
2. In Shortcuts, run **Record a Voice Note** (TinyCloud Home), then assign it to the Action button and run it there; the app opens on the recorder with the recording running.

Record each observation, including the iOS version, as pass, fail, or pending.

The release workflow checks the embedded appex identifier, WidgetKit extension point, build number, Live Activity key, and privacy manifest. The signing helper checks the app and appex signatures and their separate App Store profiles. A free Personal Team device build uses development profiles; the TestFlight release signing path uses distribution profiles and needs a paid team.
