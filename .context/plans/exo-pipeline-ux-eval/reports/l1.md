# L1: short voice-note sync

## Measurements

- Sam's dev log: at least 12 sequential TinyCloud space calls per save, median 4.1 s per call; two `transcript_persist` stages for `fdea0c6a` and `c129cb96`; 52 s audio took 140 s from Stop to saved.
- Warm-identity, one-part fixture with a local Markdown note: 10 space calls in `saveVoiceNote` (SQL, KV read/list/write). The test makes one additional SQL read to inspect the result, so its counter asserts 11. The calls form independent text and audio tracks after row creation.
- Fixed-latency fixture: ten calls at 20 ms each took 155.6 ms locally, compared with a 200 ms serial lower bound for the same ten calls (22% shorter). Sam's 12-call serial baseline at the same artificial latency would be at least 240 ms. This is a fixture measurement, not a production latency claim.
- A held audio-part PUT left the manifest absent while the Markdown KV and row metadata were present. The row already contains capture mode and platform for Private admission.
- Replayed local result triggers call transcript publication once per source ID and revision, including when the native acknowledgement initially fails. `commitVoiceNoteTranscript` and its `body_key` authority and plain-key mirror are unchanged.

## Trigger trace

Mac Whisper completion requests local transcript sync. `recordRowId` also requests it when the local result is already done, and `syncDesktopAfterUpload` requests it when the whole save finishes. They previously serialized repeat remote commits. The sync now checks the current native ledger revision and a successful publication keyed by account, source ID and revision before starting another remote commit.

## Changed path

- Row creation includes capture metadata, so Private admission can begin at the row boundary using the committed local file. Its availability check starts immediately after local commit. The post-save callback no longer starts Private again.
- Empty legacy transcript mirror and Markdown sync begin after row creation, alongside the audio transfer. Audio, short text and background drains each admit one request at a time; a held bulk part or drain cannot occupy the text lane.
- The save reuses its resolved row for audio and Markdown metadata patches, removing repeated row reads. The transcript commit protocol stays authoritative.

## Verification

- No recorder Rust changed; cargo tests do not apply.

## Remaining risks and scope

- A live TinyCloud node was not used to validate concurrent text, audio and background requests. The fixture proves orchestration and ordering, not server capacity or real wall time.
- Powerful's existing provider path still reads a cloud commit before upload. It starts at local commit, but a slow commit read can delay its provider transfer.
- Durable `retrying` status and IndexedDB persistence for held/failure reasons from the broader Opus L1 card are not included here. Existing per-part retry remains. This needs a follow-up before the full card's relaunch and backoff acceptance can be claimed.
- Overlaps to coordinate: A1 reads status selectors and job copy; #351 changes audio upload policy and controls. This slice changes the save and lane behavior that both will observe, without editing their UI or setting files.
