# A1: Activity over current voice-note state

## Implemented

- Added one `activityForNote` projection over the existing `useNotePipelines` inputs. It lists finish, transcribe, sync, and audio upload separately when the current stores report them. It does not infer queue position from the shared space lane.
- Added a quiet Activity control with a running indicator, attention mark, job progress, waiting reasons, real destinations, Copy details, Open note, and only a supported Retry action. No pause or cancel controls are present.
- Library and note detail use the same projection for one status line. The local transcript remains visible while its sync runs. The full transcript placeholder now says it is syncing instead of claiming “Transcript saved.”
- Corrected Mac, iPhone, Android phone, and browser wording in the pipeline. Powerful is identified as AssemblyAI in Activity, separately from Private. Changed unknown lane copy to “Waiting to start.”
- Removed raw store/provider messages and diagnostic references from visible pipeline errors. Activity's Copy details keeps the diagnostic text available on request.
- Removed native decoder, scan, and subscription diagnostics from the legacy on-device note detail messages; its Retry remains available and diagnostics stay in the console.
- Batched Activity, Library and detail projections to at most one update per 250 ms. Job state transitions use the existing development log.
- Memoized note rows against their rendered status; a React Profiler test confirms that one progress tick renders only its note's Activity row.

## Overlaps and limits

- #350 and T1 also edit note detail's transcript area. This slice changes only the status line and the local-text sync caption there; it does not change timestamps, channels, seeking, or transcript block rendering.
- #351 changes optional audio upload policy and note detail controls. This slice reads its `uploadAudio` intent from the native note when present and suppresses an upload job when audio is local only. The eventual merge must preserve that mapping.
- #366 adds persisted `retryAt`; this slice reads it when present and offers Try now. #363 (T1) merges cleanly; this slice leaves timestamp rendering alone.
- #366 was not on `origin/main` at r2 verification. Its merge must preserve `pending.retryAt` so Activity shows “Your TinyCloud space is slow to answer · trying again in N s” with Try now.
- The current stores do not persist completion time or independent finish/upload history. The panel therefore lists known pending work and current failures, without inventing a “Done today” inventory.
- The shared lane no longer directly publishes every busy flip into the pipeline's React selector. A timed-out space-row read still receives the lane's idle event so it can retry. The recorder and pending-note stores remain shared; a fully independent per-note external-store subscription awaits the durable job adapter.
