# N1 notifications

- Failure events come from A1's `activityForNote` selector. Successful and waiting work is silent. A shared sync/upload error produces one audio-upload notification.
- The account-scoped dedupe set stores note × track × failure fingerprints, not raw diagnostics. A failure first seen on its open note is consumed silently. Toasts close if that note becomes visible.
- Toast actions open the encoded Library note path. Mac notifications carry the same path, note ID and track in `data` and open the note on click.
- Tauri's notification plugin and Capacitor local notifications are absent. Mac uses the Web Notification API in Tauri, with an explained, lazy permission choice after the first eligible failure. iOS, Android and web use in-app toasts only; web never asks for browser notification permission.
