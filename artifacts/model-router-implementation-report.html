Runtime decision

Installed assistant-ui @assistant-ui/core 0.2.9 source establishes the actual boundary: RemoteThreadListThreadListRuntimeCore.switchToNewThread() waits for an initialization transaction, while RemoteThreadListHookInstanceManager keeps previously visited runtime providers mounted. LocalThreadRuntimeCore.append() calls the user-history append without awaiting it before starting the run.

Deliberate adjustment to plan section 3: initialization starts the memoized choice but returns the stable thread ID without waiting for health or storage. Holding that metadata transaction open makes new-thread navigation unable to commit and cancel selection. The committed main-thread subscription now establishes activation synchronously; inactive providers cannot activate themselves, and delayed sends cannot reactivate old threads. History and inference share the awaited choice; inference additionally awaits confirmation of the user append. Initialization creates no SQL row and is never permanently rejected by recoverable selection errors.

1 · Main thread
Commit navigation; cancel old activation.
2 · Choice
One lookup or saved-model restoration.
3 · Origin
Freeze space, thread, activation, model, turn ID, cancellation signal.
4 · Save
FIFO append and latest model confirmation.
5 · Inference
Bound transport, compaction, receipts and extraction.
