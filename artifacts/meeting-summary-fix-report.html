Meeting summaries get a real citation-repair chance

Regression tests reproduce a legacy-loop failure matching the Sep 11 report: finding meetings and reading summaries consumes the three-round budget before an uncited synthesis can receive citation repair. No deployment, merge, production request, or live private meeting read was performed.

The legacy loop (used when the newer structured meeting controller is not enabled) treated maxRounds: 3 as both the tool/retrieval budget and the complete synthesis budget. A one-hop request already had a repair opportunity, but a two-hop find_meetings → read_meeting(s) request consumed both preliminary rounds. If its forced clean synthesis omitted the exact supplied citation, the final presence check correctly rejected the draft but had no remaining round in which to repair it.

The pre-fix regression run demonstrated this directly: both new cases failed because only three model requests occurred where the successful path required four.

Focused change

  • A synthesis that fails exact-citation presence validation gets at most one clean-synthesis repair. It is always requested without tools; when the failed draft used the last ordinary round, only that single repair extends the limit.
  • If that one repair still omits the supplied citations, its draft stays hidden and the existing safe fallback is emitted after any already-streamed progress. The exact-citation presence check remains in place; no citation is fabricated.
  • The legacy citation gate now recognizes both meeting/read [M…] citations and transcript-search [T…] citations, preserving the full exact bracketed value supplied by the tool.
  • Tool-call metadata is accumulated before co-delivered content. Prose attached only to a private tinycloud_* call is treated as progress and omitted from assistant content; the existing typed tool_activity SSE frames remain the progress channel.
  • When a provider instead sends private-tool preamble text as standalone deltas before its later tool_calls metadata, already-emitted text is retained and the eventual validated summary or safe fallback is prefixed with a paragraph boundary. No protocol change or broad buffering was added.
  • Public-web progress and ordinary chat continue to stream exactly once. Mixed web/private failure behavior, delegation errors, usage summation, final completion identity, terminal delivery, abort handling, and the existing context truncation guards retain their established paths.

Verification limits

The exact production provider completion and chunk ordering were not available, so this report does not claim a live production root cause. The round-budget failure, co-delivered suppression, and earlier standalone-delta presentation defect are covered by realistic local SSE fixtures. Earlier standalone content cannot be retracted without changing the existing cumulative SSE contract; this patch preserves it and inserts a readable boundary only after later metadata identifies that round as private-tool progress.
